# Деградация сервисов — инфографика

PostgreSQL 18 + Adminer, бэкенд на Python (FastAPI), фронтенд на React (Vite). Всё запускается в Docker —
ставить Node и Python на компьютер не нужно.

## Запуск

```sh
docker compose up -d --build
```

| Что | Адрес |
|---|---|
| Дашборд | http://localhost:8000 |
| Описание API (можно пробовать запросы) | http://localhost:8000/api/docs |
| Adminer | http://localhost:8080 (сервер `db`, пользователь `postgres_admin`, пароль `example`, база `testdb`) |
| PostgreSQL | localhost:5432 |

Если порты заняты: `DB_HOST_PORT=55432 ADMINER_HOST_PORT=8081 WEB_HOST_PORT=8001 docker compose up -d`.

**После правок кода** образ нужно пересобрать — код попадает в него при сборке:

```sh
docker compose up -d --build backend    # правили backend/
docker compose up -d --build frontend   # правили frontend/
```

Для быстрой работы над страницей можно запустить Vite с мгновенным обновлением (нужен Node 22+ на компьютере):
`cd frontend && npm install && npm run dev` — страница откроется на http://localhost:5173, а запросы `/api/*`
уйдут в запущенный `docker compose`.

## Как это устроено

```
браузер ──> frontend (nginx) ──┬── страница: собранный React (html, js, css)
           порт 8000           └── /api/* ──> backend (uvicorn + FastAPI) ──> db (PostgreSQL)
```

- **frontend** — при сборке образа Node собирает React-приложение из `frontend/src` в обычные файлы (`npm run build`),
  а nginx их раздаёт и передаёт запросы `/api/*` в backend.
- **backend** — один метод `GET /api/data?from=2026-01-01&to=2026-03-31`: данные дашборда за период одним ответом
  в JSON. Без `from` и `to` — за последний месяц, где есть данные. Ошибки — `{"error": "текст"}` с кодом
  400 (неверные даты), 404 (нет случаев или такого метода) или 500 (ошибка базы).

## Данные

Схема — в `db/01-schema.sql`, демо-данные — в `db/02-data.sql`. Postgres загружает их сам при первом старте с пустым томом.

Каждый случай деградации хранится отдельной строкой `degradation_case` с диапазоном деградации `bucket_id` и датой `case_date`. Точный процент не хранится: авария определяется тем, в какой диапазон с шагом 10 она попала (таблица `bucket`: 0–10%, 11–20%, … 91–100%). Данные есть за каждый месяц с сентября 2025 по октябрь 2026; на дашборде период выбирается в списке «Период»: месяц, год или произвольный диапазон дат «с … по …» (по умолчанию — последний месяц). Сервер всегда получает две даты: месяц и год страница сама превращает в первый и последний день (`frontend/src/period.js`).

Степени деградации (минимальная, частичная, значительная, полная — названия по МУ) считаются по диапазону, границы по умолчанию: минимальная 0–20%, частичная 21–50%, значительная 51–80%, полная 81–100% (`STEPEN_BOUNDS` в `frontend/src/config.js`). У отдельного сервиса можно задать свои границы: нажать на его название (чип) в таблице, в открывшемся окне передвинуть границы на шкале-ползунке (ручки тянутся мышью или стрелками клавиатуры; над каждой — плашка с числом и стрелками, шаг 10%) и сохранить. Ненужную степень можно отключить тумблером в её карточке (ещё одно нажатие включает её снова): её проценты забирает соседняя степень, и границы настраиваются только между оставшимися. Например, если отключить всё, кроме минимальной, вся шкала 0–100% — минимальная; «Вернуть по умолчанию» возвращает границы по умолчанию (применяются тоже по «Сохранить»). У чипа такого сервиса чёрная обводка, у остальных — серая пунктирная. Свои границы живут только на странице (состояние `serviceBounds` в `App.jsx`): на сервер не отправляются, при смене периода сохраняются, после перезагрузки страницы сбрасываются.

Продукты (таблица `product`) — верхний уровень: в продукте операции, в операции сервисы. Диапазоны `bucket` задают и колонки таблицы «как в Excel».

**Демо-данные синтетические.** Октябрь 2026 — данные из `пример.xlsx`: количество случаев по диапазонам совпадает с исходной таблицей, даты — с 1 по 10 октября. Сентябрь 2025 — сентябрь 2026 сгенерированы по образцу октября. Когда будут реальные данные, их нужно загрузить вместо блока `degradation_case` в `db/02-data.sql`.

Чтобы перезалить данные после правки этих файлов:

```sh
docker compose down -v && docker compose up -d
```

## Структура

```
compose.yaml                 сервисы: db, adminer, backend, frontend
docker/db/Dockerfile         PostgreSQL с русской локалью (ICU)
db/                          схема и демо-данные

backend/                     Python
  Dockerfile, requirements.txt
  app/main.py                FastAPI: адрес /api/data, проверка дат, ответы и ошибки
  app/data.py                запросы к базе и сборка ответа
  app/db.py                  подключение к базе

frontend/                    React
  Dockerfile, nginx.conf     сборка (Node) и раздача (nginx), /api/* -> backend
  index.html, vite.config.js
  public/                    шрифты и иконка — отдаются как есть
  src/main.jsx               точка входа (там же — что в каком файле)
  src/App.jsx                вся страница: состояние и загрузка данных
  src/components/            части страницы: фильтры, блок метрики, кольцо, полосы, таблица, окно сервиса, подсказка
  src/calc.js, bounds.js, period.js, api.js, helpers.js, config.js — расчёты и помощники без React
  src/style.css              стили
```
